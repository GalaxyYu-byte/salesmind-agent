# 意图解析评测

15 组、27 轮固定用例，预期定义在 `tests/intent_cases.py`。每组使用独立会话，组内 question 创建新任务，reply 沿用等待补充的任务。参考日固定为 2026-10-08、时区 Asia/Shanghai，区域目录为华东（1）、华南（2），商品目录为商品甲（1）、商品乙（2），数据覆盖 2024-02-01 至 2026-09-21；2026-09 尚不是完整可查询月。

| 组 | 问句与多轮输入 | 预期 |
|---|---|---|
| 01 | 2026年8月华东销售额走势如何？ | amount / 2026-08 / 华东 / trend，查询一次 |
| 02 | 华东卖了多少钱？ → 2026年8月 | 先追问 months、零查询；补齐后查询一次 |
| 03 | 看看华东 → 按销售额统计 → 不看华东了，改成2026年7月华南订单数 | 前两轮分别缺 metric+months、months，零查询；最后采用全部更正，count / 2026-07 / 华南 |
| 04 | 最近华东销售额走势如何？ → 不是销售额，改看毛利 → 2026年7月至8月 | 模糊时间不猜范围；改指标后仍只追问 months；最后 profit / 7–8月 / 华东 / trend |
| 05 | 2026年8月华东平均客单价走势 → 华南呢？ | 保留 average、月份、trend，只改区域，重新查询 |
| 06 | 新会话：华南呢？ → 看2026年8月华南订单数汇总 | 缺 context 时零查询，不继承其他会话；补齐后 count / 2026-08 / 华南 |
| 07 | 2026年8月火星区销售额多少？ → 区域改成华南 | 未知区域追问 region，不能用全部区域代替；改正后查询 |
| 08 | 2026年8月华东净利润多少？ | unsupported，零查询；不能把净利润当成毛利 |
| 09 | 2026年8月华东销售额多少？ → 改看转化率呢？ | 第一轮查询；第二轮 unsupported，不能继承销售额继续查询 |
| 10 | 上个月华东销售额多少？ → 那改成2026年8月 | 上个月为九月，水位不足应追问 months；不能静默改成八月，明确更正后才查询 |
| 11 | 2026年8月华东销售额环比如何？ | comparison=mom，汇总比较紧邻的前一等长期间 |
| 12 | 比较2026年8月华东商品甲和商品乙销售额 → 环比呢？ | 服务端解析 product_ids=[1,2]，环比追问继承商品筛选 |
| 13 | 比较2026年8月华东火星商品销售额 → 商品改成商品甲 | 未知商品先追问 products、零查询，不能扩大成全部商品 |
| 14 | 检测2026年7月至8月华东销售额异常，比较前6个月均值，偏差阈值40% | goal=anomalies，trend，window=6、threshold=40，不叠加同比/环比 |
| 15 | 比较2026年8月各区域销售额环比，找出下降最多的区域 | regions/mom/mom_percent/asc/top_n=1 |

## 运行

离线回归不调用模型，只检验给定提取结果在真实会话 API、SQLite 持久化和 LangGraph 中的条件校验与查询阻断：

```powershell
uv run pytest tests/test_intent_evaluation.py -q --intent-report=evals/results/intent-offline-latest.json
```

真实提取评测使用 `.env` 或环境变量中的模型配置，逐轮调用 `IntentParser`。业务目录固定，销售聚合查询用 spy 记录调用次数，不连接开发业务库或应用库；会产生模型 API 调用费用。

```powershell
uv run pytest tests/test_intent_evaluation.py -q --intent-live --intent-report=evals/results/intent-live-latest.json
```

报告同时输出 JSON 与 Markdown。JSON 保存每轮预期、通过原文校验后的 draft、模型输入（原问题、补充回答、上一轮条件）、归一化条件、指标原词与校验状态、任务状态、查询参数、查询次数与节点启动记录；不保存 API Key 或请求头。失败返回非零退出码。用 `-k 08-unknown-metric` 可单独复跑一组；此时报告总数仍为完整用例集，未运行用例不计通过。

## 2026-10-08 实测

新增模板的离线复测：**15/15 组、27/27 轮通过**，见 [模板扩展离线报告](results/intent-offline-templates.md) 和 [逐轮 JSON](results/intent-offline-templates.json)。环比、商品及异常用例未调用真实模型，以下真实模型数字仅对应原有 10 组、20 轮。

- 离线：10/10 组、20/20 轮通过。这验证查询阻断链路，不代表自然语言准确率。
- 真实模型 `deepseek-flash`：8/10 组、18/20 轮通过。这是固定小样本的一次运行。
- 第 04 组第二轮：模型保留了毛利、华东和趋势，但误设 `follow_up=true`。没有已完成的上一轮分析，后端追问 `context`，预期应只追问 `months`。本轮零查询，最终补齐月份后正常完成。
- 第 08 组：模型将“净利润”提取成 `metric=profit`、`unsupported=false`。后端因此完成毛利查询，实际调用一次销售查询替身，预期为 unsupported、零次。修复前的白名单只能阻挡非法枚举，无法发现这种合法枚举中的语义错误。

原始结果见 [真实模型报告](results/intent-live.md)、[逐轮 JSON](results/intent-live.json) 和 [离线报告](results/intent-offline.md)。首次评测仅记录问题；随后按下面的修复方案复测，原有问句、状态、查询参数与查询次数预期保持不变。

## 修复后的复测

- 解析增加原始指标词与 supported / unknown / ambiguous 状态，服务端校验原文证据与已注册别名，查询白名单保留。
- 原文中的净利润、转化率等防错词即使被模型误写成毛利、遗漏或继续继承，也会阻断；口径不明确的“利润”先澄清。模型声明 supported 本身不能放行查询。
- 未注册的指标原词不映射到邻近口径；后面的明确指标更正优先，否定净利润后改看毛利可以正常执行。多个指标不能因“换成柱状图”而被当成单指标。
- 无已完成历史的任务补充回复继续累计解析，误报 follow_up=true 不再触发缺少 context；真正跨任务追问仍可继承。
- 新增针对故意错误模型输出、指标原词持久化/事件、更正和历史边界的回归。最终相关离线测试 **104 项通过**，Ruff 检查与格式检查通过；另有两个既有取消边界测试单独核对（见下方验证说明）。
- 同一批真实模型问句复测 **10/10 组、20/20 轮通过**。“净利润”请求的 query 节点未启动，销售查询次数为 0；毛利更正后只追问 months，补齐时间后查询一次。

结果见 [修复后真实评测](results/intent-live-after.md)、[逐轮 JSON](results/intent-live-after.json) 和 [修复后离线评测](results/intent-offline-after.md)。这仍是固定小样本的一次复测，不代表所有自由问法的准确率。

验证说明：组合回归中，两个既有 SQLite 取消边界测试曾间歇返回 503；最终 104 项通过的运行排除了这两项。它们随后单独复跑及有限重复诊断共 32 次均通过，未捕获原始异常。本次未修改取消分支，目前没有证据确认根因或与本次改动的因果关系；该偶发异常仍待单独调查。
